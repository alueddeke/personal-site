Auth today (backend/config/auth.py): CsrfExemptSessionAuthentication (session/cookie based).
Profile page (frontend/app/profile/page.tsx): server component reads `sessionid` cookie, redirects to `/` if absent, then fetches /api/get-user-name/.
Frontend HTTP (frontend/services/axios.ts): axios withCredentials:true, sends csrftoken header.

Demo Mode design (NEW — this plan):
- Backend `DEMO_MODE` (env, default False). When True, a DRF authentication class resolves request.user to a seeded demo User on every request — NO session cookie required. This removes per-user login AND the cross-domain cookie requirement.
- Seed one demo User whose UserProfile stores a Spotify REFRESH token (captured via one real local login). Backend uses spotipy to refresh access tokens for gem regen / candidate generation on the demo account's behalf.
- Destructive Spotify writes (POST /api/add-track-to-liked/) are guarded/no-op in DEMO_MODE so visitors can't mutate the real account's Spotify library.
- Frontend `NEXT_PUBLIC_DEMO_MODE=true`: profile page skips the sessionid redirect; landing `/` offers a direct "Open demo" path into /profile; a persistent banner explains the single-account limitation.

Key endpoints (backend/apps/core/views.py): GET /api/daily-gem/ (?force_new=true), POST /api/submit-feedback/, POST /api/submit-ai-feedback/, GET /api/recommendation-metrics/, GET /api/recommendation-trend/, POST /api/add-track-to-liked/ (guard in demo), GET /api/get-user-name/, /spotify/callback/.

Prod hardening required (HANDOFF_DEPLOY.md §4): DEBUG=False, ALLOWED_HOSTS, dj-database-url → Postgres, WhiteNoise + STATIC_ROOT + collectstatic, gunicorn start, requirements add: gunicorn, psycopg2-binary, whitenoise, dj-database-url.
